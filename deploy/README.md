# 服务器部署

要求 Docker Compose，域名指向服务器，80/443 可用。局域网需自行部署受访问设备信任的 HTTPS 证书。

1. 复制 `.env.example` 到 `.env`，填写 DOMAIN、ADMIN_PASSWORD、DASHSCOPE_API_KEY 与评分模型配置。
2. `QWEN_OMNI_WS_URL` 必须是供应商实时 WebSocket 端点，不是 OpenAI 兼容 HTTP 地址。账号必须有目标模型权限。评分服务使用 DEEPSEEK_* 兼容配置。
3. 执行 `docker compose --env-file .env up -d --build`。
4. 检查 `docker compose ps` 与 `docker compose logs --tail=100 app`。
5. `/api/health` 应返回 200 且数据库 up(数据库不可用时返回 503，容器会被标记为 unhealthy)；匿名 `/api/sessions` 返回 401；管理员登录成功。
6. 使用专门测试候选人完成邀请→授权→面试→结束→报告流程，再交付。

数据库保存在 interview_data 卷。禁止在保留数据时运行 `down -v`。数据库使用 WAL 模式：备份 SQLite 时停止 app(停止时 WAL 会合并回主文件)，再复制数据库文件(若存在 `-wal`/`-shm` 文件一并复制)到独立备份存储，随后启动 app；恢复前保留原数据库，验证恢复后记录完整。升级前记录旧镜像 ID 并备份数据库，回滚代码不要覆盖新产生的记录。

Caddy 负责 TLS，应用负责管理员验证。不要将开发服务器直接暴露公网。管理员密码放在服务器 .env，不写入 Git。仅将经批准的客户数据迁移到新服务器；默认新建空数据库。

当前为单组织版本。多人权限、操作审计、备份自动化、数据删除/保留策略与公网访问限流，需要根据客户合同进一步配置。

## 运行时保护

- 管理员密码连续输错 10 次，该来源地址 5 分钟内返回 429。更换密码后重启 app 可立即清除计数。
- 面试链接一次有效：面试结束后同一链接不能再次进入，需在后台重新生成。
- 面试到达职位设定时长后再保留 5 分钟收尾，随后服务端自动结束，避免挂起的连接持续消耗实时模型额度。
- 页面默认下发 Content-Security-Policy(仅允许本站脚本、样式与媒体)。若需接入外部资源，可用环境变量 `CONTENT_SECURITY_POLICY` 覆盖，设为空字符串则关闭。
- 已有面试记录的职位不能删除，请改为“已关闭”。

## 面试后诚信分析

面试结束后、生成报告前，系统会自动计算三类线索并写入报告页的“诚信检测”：

- **回答前停顿模式**：多个长回答开口前都停顿相近的时长。纯服务端计时，无需额外配置。
- **追问表现落差**：主问题得分高、追问细节得分低。需要 `DEEPSEEK_API_KEY`。
- **与 AI 答案的相似度**：让评分模型对同一问题生成参考答案，再用向量模型比较。需要 `DEEPSEEK_API_KEY` 和向量服务；默认复用 `DASHSCOPE_API_KEY` 调用百炼的向量接口，也可用 `EMBEDDING_BASE_URL` / `EMBEDDING_MODEL` 指向自建的开源模型（如 bge-m3）。

每场面试额外消耗：1 次逐题评分调用，加上最多 6 个长回答各 1 次参考答案生成和 1 次向量调用。任何一项服务不可用时只会少一条线索，不影响报告生成。这些线索仅供人工复核，不应作为自动淘汰依据。
